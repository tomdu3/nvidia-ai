WHAT IS UV
- A modern Python package installer and resolver written in Rust.
- Works like pip but is much faster because of its Rust implementation.
- Can create isolated virtual environments and manage project dependencies from a single tool.

WHY USE UV
- Speed: installs packages in a fraction of the time compared to traditional tools.
- Simplicity: one command handles project creation, environment setup, and dependency management.
- Compatibility: reads and writes standard files like pyproject.toml and requirements.txt.
- Reduces the need to manually activate environments; uv run can execute scripts directly.

GETTING STARTED: INSTALL UV
- On macOS or Linux run the installer script:
  curl -LsSf https://astral.sh/uv/install.sh | sh
- On Windows open PowerShell and run:
  iwr https://astral.sh/uv/install.ps1 -useb | iex
- Verify the installation:
  uv --version
- Make sure the installer added uv to your system PATH; if not, add the folder manually.

CREATING A NEW PROJECT
- Create a fresh project with:
  uv init my_project
- This generates:
  - pyproject.toml (holds project metadata and dependencies)
  - .python-version (optional, pins the Python version)
  - A source folder (src/ or my_project/) for your code
- Move into the project folder:
  cd my_project

MANAGING THE PYTHON VERSION
- uv can install a specific Python version for the project:
  uv python install 3.11
- Pin that version for the project:
  uv python pin 3.11
- Subsequent uv commands will use this Python version when creating the virtual environment.

ADDING DEPENDENCIES
- Add a regular dependency:
  uv add requests
- This updates pyproject.toml and creates/updates uv.lock (the lock file).
- Add a development‑only dependency:
  uv add --dev pytest
- Remove a dependency:
  uv remove requests

INSTALLING DEPENDENCIES FROM AN EXISTING FILE
- If you have a requirements.txt, you can install it with:
  uv pip install -r requirements.txt
- For new projects it’s better to use uv add to populate pyproject.toml directly.

RUNNING CODE
- Execute a script inside the project’s environment:
  uv run python script.py
- Run a module (like a simple HTTP server):
  uv run -m http.server
- uv run automatically creates a temporary virtual environment if none exists and uses it.

SYNCING THE ENVIRONMENT
- After cloning a repository, make sure the environment matches the lock file:
  uv sync
- This installs the exact versions recorded in uv.lock, ensuring reproducibility.
- Use this step in CI/CD pipelines or when onboarding new team members.

UPGRADING PACKAGES
- Upgrade a specific package:
  uv upgrade requests
- Upgrade all packages to their latest allowed versions:
  uv upgrade
- uv respects the version constraints you set in pyproject.toml.

REMOVING THE VIRTUAL ENVIRONMENT
- The environment is stored in a folder called .venv by default.
- To delete it manually:
  rm -rf .venv   (on macOS/Linux)   or delete the folder via Explorer (on Windows)
- uv will recreate it the next time you run uv run, uv sync, or uv add.

COMMON WORKFLOW EXAMPLE
- uv init my_web_app
- cd my_web_app
- uv add flask
- uv run python -c "import flask; print(flask.__version__)"
- uv add --dev pytest
- uv run pytest   (runs your tests inside the project environment)

TIPS FOR BEGINNERS
- Keep pyproject.toml and uv.lock under version control (e.g., git) so teammates get identical setups.
- Use uv run instead of manually activating a venv; it avoids mistakes with its; it’s simpler and less error‑prone.
- If you ever need to run pip directly inside the uv environment, you can do:
  uv pip install <package>
- uv works well with IDEs like VS Code; just point the Python interpreter to .venv/bin/python (or .venv\Scripts\python.exe on Windows).
- Start small: create a project, add a dependency, run a script, and observe how uv handles everything behind the scenes. Happy coding!
